## 项目说明

单文件交互应用 `index.html`，纯原生 HTML5 Canvas 实现，无任何外部依赖，**双击即可在浏览器中运行**。

### 功能清单

**基础功能**

- 深灰科技风背景（`#1a1a24`），摆球带微弱发光光效；
- 基于角加速度微分方程 `α = -(g/L)·sin(θ) - k·ω` 的物理仿真，`requestAnimationFrame` 驱动动画循环，半隐式欧拉积分 + 子步进保证数值稳定；
- 3 个参数滑块实时联动：摆长（100~350 px）、重力（1~25）、阻尼（0.000~0.010）；
- 「重置摆动」按钮：摆球精准回到 45° 初始状态。

**进阶挑战 B（选做，已实现）**

- 4 个天体胶囊按钮（地球 9.8 / 月球 1.6 / 木星 24.8 / 太空 1.0），点击后重力**平滑过渡**并自动联动滑块；
- `localStorage` 自动保存用户自定义参数，刷新页面后自动恢复上次的摆长、重力与阻尼设置。

## 人机协同三反思

### 1. 意图清晰度反思

最初生成 MVP 时，我只跟 AI 说「做一个单摆动画」，结果第一版摆球摆动得飞快、完全没有物理感。回看那条提示词，缺少了**约束（Boundary）**：没有给定摆长、重力、初始摆角的具体数值，也没有说明用什么方程驱动。后来我按「黄金三角」补齐了四段式——角色（前端可视化与物理仿真工程师）、目标（单文件单摆模拟器）、约束（Canvas 原生绘制、初始 L=200px / g=9.8 / 45°、requestAnimationFrame 循环）、验收标准（双击打开流畅摆动），AI 一次就交出了符合预期的版本。这让我意识到：**AI 生成质量的上限，取决于我意图表达的下限。**

### 2. 闭环控制反思

在绑定期遇到过一次典型故障：点击「重置」按钮没有反应。我没有对 AI 说「坏了，重写」，而是按 F12 打开控制台，复制了完整的红色报错堆栈喂给 AI。AI 随即进入 ReAct 循环——先反思根因（按钮的事件绑定写在了脚本顶部，此时 DOM 尚未渲染，监听器挂空），再执行外科手术式修复（把绑定逻辑移到 DOM 就绪之后，并统一用 `addEventListener` 替代内联 `onclick`）。我看懂了它的修复思路：问题不在物理公式，而在**脚本执行时机与事件作用域**。刷新后控制台 0 报错，功能恢复。证据驱动的反馈比情绪化抱怨高效得多。

### 3. 主体地位确认

作为 HOTL（人在回路之上）的产品总设计师，**核心决策全部由我做出**：选择深灰科技风的视觉基调、决定滑块的参数范围、拍板做「天体预设 + 持久化」这个进阶方向、以及每一次「这个效果行不行」的验收判断。AI 完成的是重复劳动：Canvas 绘制样板代码、物理积分循环、事件绑定与边界处理。我提需求、设边界、看效果、给反馈；AI 负责把意图翻译成能跑的代码。方向盘始终在我手里，AI 是引擎。
